# rtsdk — 干渉を「走らせて見つける」から「書けなくする」へ

3D 設備の空間セマンティクス (どこに何が居てよいか) と時間軸の因果 (いつ何が起きるか) を、
**型システム**の側で結んだ最小 PoC。

現場の資産 (C++) はそのまま残したまま、

* 2 本のアームが同じゾーンに入るコードを**書けなくする** (型状態 + 排他トークン)、
* 手順の最悪実行時間を**走らせる前に足し上げる** (仮想時間モナドの関連定数)、
* 図面の約束を**そのまま `#[test]` にする** (空間セマンティクス DSL)、
* 落ちた瞬間の因果を**時間を巻き戻して**見る (パルスグラフ + タイムトラベル)

の 4 つが繋がっていることを、動くコードで示す。

```bash
cd rtsdk
cargo test                                    # 全部緑
cargo test -p sim-harness --lib -- --ignored  # TDD の赤 (包む前の姿) を見る
cargo run -p sim-harness --bin dump-traces -- artifacts   # 波形を JSON に出す
```

対象環境は産業用 IPC (Linux/PREEMPT_RT、ROS 2 / EtherCAT) を想定。
SDK 側 3 クレートは `no_std` + 動的確保なしなので、そのまま Wasm (wamr / wasmtime AOT) に載る。

## 1. クレート構成

```
rtsdk/
├─ proto/pulse.proto            交換形式 (Rust 側は依存なしの varint 直書きで 1 対 1)
├─ artifacts/                   走行のトレース (UI が読む / git に入れてある)
└─ crates/
   ├─ pulse-trace   no_std  事象の型と固定長レコーダ。制御 / 検証 / UI が共有する唯一の語彙
   ├─ vtime         no_std  仮想時間モナド。Δt 注入、WCET を型で加算、周期予算の静的検査
   ├─ zoneguard     no_std  型状態のアーム、ゾーンごとに 1 枚の排他トークン、固定小数の幾何
   ├─ legacy-bridge std     C++ 資産を unsafe で包む層 + 決定的な離散事象スケジューラ
   ├─ sim-harness   std     空間セマンティクス DSL、シミュレータ、TDD ランナー
   └─ ui-pulse      wasm    パルスグラフ (egui)。重ね合わせ・因果矢印・タイムトラベル
```

依存は一方向に流れる。

```
pulse-trace ─┬─ vtime ─┬─ zoneguard ─┬─ legacy-bridge ─┬─ sim-harness
             │         │             │                 │
             └─────────┴─────────────┴─────────────────┴─ ui-pulse (pulse-trace のみ)
```

`no_std` の 3 つは `alloc` すら持ち込まない。`Vec` も `Box` も `dyn` も出てこないので、
確保の失敗も伸長による WCET の揺れも、**型の上に存在しない**。
std を使うのは「設備を模す側」と「テストする側」だけ。

外部依存は 2 つ (`cc` = C++ のビルド、`egui` = 描画) で、制御側には 1 つも無い。

## 2. 題材 — 何が壊れているのか

2 本のアームが、1 つのワークエリア (ゾーン X) を左右から取り合う。
排他は 30 年もののコードで `g_busy` というフラグ 1 個。

```c
/* crates/legacy-bridge/cxx/arm_ctl_1998.cpp */
if (g_busy) {
    g_sleep(1000);   /* ← 待つだけ。待った後に再確認しない */
}
g_busy = 1;          /* (1) 見る と (3) 書く の間に、送りループの待ちが挟まる */
```

これは排他ではなく「たいてい当たる時間差」でしかない。
タクトを詰めた日か、サーボを速い型に替えた日に、当たらなくなる。

このファイルは **1 行も直さない**。唯一の改造は `usleep` と軸書き込みを
関数ポインタにしたことだけで、ロジックには触れていない。

## 3. 段階的に包む

### 段 1: `unsafe` で生のまま呼ぶ

`ffi.rs` に前提を文章として書き出す。プロセスグローバル、フック先行、軸は 0..2、再入不可。
以降の層は、この 4 つを守る責任を負う。

### 段 2: 実時計を仮想時間に差し替える

`legacy_hook_sleep_us` の先を、実時間の睡眠から**離散事象**に変える。
実行権 (バトン) をプロセス内に 1 枚しか置かず、
「起床時刻の小さい順、同着ならタスク番号順」で配る (`vsched.rs`)。

結果:

* 仮想 5 秒のシナリオが実時間 2 ms で回る (テストで確認している)、
* **同じ入力なら必ず同じ順序**。競合が「たまに再現するバグ」から「毎回同じ時刻に出る反例」になる。

```
cargo test -p sim-harness --lib -- --ignored

[cell01] 規則 0 (SEPARATION) が破れている
  ARM_A と ARM_B の表面間が 48000 µm まで詰まった (下限 50000 µm) @ t=15000 µs
[cell01] 規則 1 (EXCLUSIVE_X) が破れている
  排他ゾーン ZONE_X に ARM_A と ARM_B が同時に入った @ t=15800 µs
```

### 段 3: 手順だけ型安全 SDK へ移す

**送りループ (`legacy_arm_move`) はレガシーのまま使う。** 加減速もサーボの癖もそこに入っている。
移すのは外側 — 排他と順序だけ。

```rust
Enter::new(arm_a, permit, APPROACH_UM)   // 許可証を消費してゾーンへ
    .bind(|a| Work::new(a, PICK_UM))     // Inside<ZoneX> を受ける手続きしか繋がらない
    .bind(|a| delay_us(HOLD_US).map(move |_| a))
    .bind(Leave::new)                    // 許可証が戻る
    .bind(move |(a, permit)| {           // B の Enter は A の Leave の出力からしか作れない
        Enter::new(arm_b, permit, APPROACH_UM)
        ...
    })
```

これで全規則が緑になる。

## 4. 型で消えているもの

`cargo test` に含まれる `compile_fail` doctest が、以下を毎回確かめている
(**通ってしまったらテストが落ちる**)。

| 書こうとしたこと | 何が起きるか |
|---|---|
| 2 本目のアームを同じゾーンへ入れる | `Permit<ZoneX>` は 1 枚しか無く、1 本目の型状態へ移動済み。**渡すトークンが無い** |
| アームがゾーンに居る間にコンベアを回す | `&Permit<ZoneX>` を借りる先が無い。`Inside<Z>` は許可証を取り出す口を持たない |
| 可達長 100 mm のアームに 250 mm 先のゾーン作業を割り付ける | const generics の単相化時アサーションでビルドが落ちる |
| 76 µs の手順を 50 µs 周期に載せる | `Budget<P, PERIOD>::FITS` の静的アサーションでビルドが落ちる |

「実行時に検知して止める」ではなく、「その状態へ至るコードが存在しない」。

## 5. 時間 — WCET を型の上で足す

```rust
impl Prog for Bind<M, F, N> {
    const WCET_US: Micros = M::WCET_US + N::WCET_US;   // 合成した瞬間に和が決まる
}
```

手順を組み立てた時点で全体の WCET がコンパイル時定数になる。
`vtime::Budget::<PickCycle, 1_000>::FITS` は 1 ms 周期に載ることの静的な証明で、
載らなければビルドが通らない。

申告値が絵に描いた餅でないことは、実際に走らせた計上値との一致で見ている
(`declared_wcet_matches_what_the_composition_charges`: 76 µs = 76 µs)。

待ち (`Delay`) は仮想時計を進めるが CPU を食わないので WCET には入らない。
設備の時間と制御タスクの時間を混ぜないための区別。

## 6. 空間セマンティクス → `#[test]`

図面の約束を 1 か所に書くと、規則 1 本ごとに `#[test]` が生える。

```rust
semantics! {
    scene cell01 "2 本のアームが 1 つのワークエリアを左右から取り合う" {
        bodies {
            [ARM_A: axis 0, base (0, 0, 0), dir (1, 0, 0), radius 30_000]
            [ARM_B: axis 1, base (400_000, 0, 0), dir (-1, 0, 0), radius 30_000]
        }
        zones {
            [ZONE_X: id 1, center (200_000, 0, 0), half (50_000, 60_000, 60_000)]
        }
        rules {
            [SEPARATION: separation(ARM_A, ARM_B) >= 50_000]
            [EXCLUSIVE_X: exclusive(ZONE_X)]
            [TACT: deadline <= 400_000]
        }
        verify {
            [green typed_sdk = crate::runners::run_typed_sdk]
            [red legacy_raw = crate::runners::run_legacy_raw]
        }
    }
}
```

生成されるもの:

```
scenes::cell01::typed_sdk::SEPARATION    ... ok       ← 緑側は常時走る
scenes::cell01::typed_sdk::EXCLUSIVE_X   ... ok
scenes::cell01::typed_sdk::TACT          ... ok
scenes::cell01::legacy_raw::SEPARATION   ... ignored  ← 赤側は --ignored のときだけ
scenes::cell01::legacy_raw::premise_is_still_red ... ok
```

赤を `--ignored` に伏せてあるのは CI を常時赤にしないため。代わりに
`premise_is_still_red` が「出発点がまだ赤いか」を毎回確かめる —
レガシー側が誰かに直されたら、TDD の前提が変わったこととして気づける。

判定は**軸が動いた都度**行う。周期サンプリングだと
「サンプルとサンプルの間だけ 50 mm を切って戻った」を取り逃がす。

## 7. 現場の回避策も測れる

「時間差でかわす」は緑になる。ただしそれは設計の性質ではない。

| 2 本目の起動遅れ | 結果 |
|---|---|
| 0 〜 10 ms | 干渉する |
| **15 ms 以上** | 当たらない |

境界 (この設備定数では 15 ms) はテストが自分で見つける
(`the_field_workaround_is_green_but_only_by_timing`)。
サーボ速度か保持時間の定数を 1 つ変えれば動く類のもので、
「当たらないこと」の証明にはならない — というのが、この表の使い道。

## 8. パルスグラフ (ui-pulse)

横軸 µs、縦軸レーン。Wasm インスタンスの起動 / 実行中 / 消滅を DAW のブロックとして描く。

* **重ね合わせ** — 型安全 SDK が意図した並び (細い枠) の上に、実測 (塗り) を重ねる。
  片側にしか無い事象と、1 ms 以上のずれが右のパネルに出る。
* **因果** — 違反から、原因になった 2 本の進入へ赤い矢印。
* **タイムトラベル** — 波形をクリックすると、その時刻の軸位置・保持トークン・ゾーン占有が出る。
  実機のダンプではなく事象の再生なので、何度でもどこへでも戻れる。

描画に依らない側 (`timeline.rs`) と描画側 (`app.rs`) を分けてあるので、
画面を出さずに全部テストしてある — 焼き込んだ実トレースに対して、
因果矢印が 2 本の進入に戻ること、干渉時刻に巻き戻すと 2 本ともゾーン内に居ることまで含めて。

```bash
cargo test -p ui-pulse                    # 描画に依らない側 (既定)
cargo check -p ui-pulse --features gui    # Canvas 描画まで
```

## 9. この PoC が示していないこと

* **実機の WCET は測っていない。** `CMD_WCET_US = 12` は申告値で、
  実測 (cyclictest / トレース) で裏を取る手順は別に要る。型が保証するのは
  「申告値の合成が正しく足される」ことと「予算を超えたら止まる」ことだけ。
* **PREEMPT_RT の並べ替えは決定的ではない。** ここでは最悪の並びを人為的に作って先に踏んでいるが、
  実機のスケジューラが同じ並びを選ぶ保証は無い。仮想時間で踏めるのは
  「その並びが起きたら壊れる」の側で、「その並びが起きない」の側ではない。
* **ゾーンは AABB、剛体は包絡球。** 実機の形状はこれより複雑で、
  精密な干渉判定を入れると評価コスト自体が WCET に効いてくる。
* **マルチゾーンのデッドロックは扱っていない。** 許可証を 2 枚要求する手順を書けば
  循環待ちが作れる。型で防ぐには取得順序を型に載せる必要があり、未実装。

## 10. tetris-vla の制御をこの基板へ移す

このリポジトリの本体 (Python) では、ピンボール題材で **ラダー / シーケンサ / VLA / VLM の
4 層が別のクロックで同居する**ところまでを測った。そこで出た性質は
どれも rtsdk の語彙にそのまま乗る。移すなら次の順序で、各段で「移す前と後で
同じ結論が出るか」を確かめながら進める。

### 段 A: 既存の実測ログを波形に写す (1 日)

`results/pinball.json` の tick 列を [`pulse_trace::Ev`] に写す変換器を書くだけ。
コードは 1 行も移さずに、既存の走行が UI のパルスグラフに乗る。
レーンは ladder / sequencer / VLA / VLM の 4 本。
**この段の価値は、移植の判断材料が絵で出ること** — 4 層のクロックのずれが、
表の数字ではなく重なりとして見える。

### 段 B: ラダーとシーケンサを Rust へ (1〜2 週)

`Rung` / `LadderPLC` は標準ライブラリしか使っておらず、
評価順が意味を持つ以外の依存が無い ([docs/code-map.md](../docs/code-map.md) の移植単位)。

* ラング 1 本 = `Compute<_, _, W>`。WCET を申告し、スキャン全体の和が型で出る。
* スキャン周期 = `Budget<Scan, PERIOD_US>::FITS`。載らなければビルドが落ちる。
* 盤面のジグと受け皿 = `semantics!` の `bodies` / `zones`。
  「口を狭くする」は `half` の値、「保持に時間をかける」は `deadline` 規則になる。
* 既存の `tests/test_pinball.py` が固定している仕様 (評価順、隠れ状態が
  テレメトリに漏れないこと) を、Rust 側の `#[test]` と**両方**回す。
  片方だけ落ちたら、どちらかの実装が嘘をついている。

隠れ状態 (耐久値) が制御層に漏れない件は、rtsdk では `Sink` に出さないこと
= 型の上で表せる。Python 側の「テレメトリから外す」規約より強い。

### 段 C: 上位層 (VLA / VLM) を仮想時間に載せる (2〜3 週)

* 推論レイテンシは `Delay` として**注入**する。実測の分布はそのまま使えて、
  「助言の古さ 1.2 秒 = 1 拍」の実験が仮想時間で再現できる (実時間を待たずに)。
* action chunking は「1 回の `Prog` が N tick ぶんの指令を配る」形になる。
  `1 推論あたりのカバー時間 ÷ レイテンシ > 1` という条件を、
  `deadline` 規則として書いて harness に境界を探させる —
  いま `the_field_workaround_is_green_but_only_by_timing` が
  ずらし量の境界 (15 ms) を自分で見つけているのと同じやり方。
* VLA 層は Wasm ゲストとして分離し、ホスト (rtsdk) が Δt を注入する。
  モデルが落ちても遅れても、下位のタクトは仮想時間の側で守られる。

### 移して初めて言えるようになること

いまの Python 側は「1 タクト以内なら遅れは無害」を**測って**示している。
rtsdk へ移すと、同じことを **タクトを超える構成はビルドが通らない** として書ける。
測定は反例が出るまで正しく、型は反例が存在しないことを言う。
4 層のうち下 2 層 (ラダー / シーケンサ) は後者に置ける — というのが移植の狙いで、
上 2 層 (VLA / VLM) は本質的に測定の側に残る。
